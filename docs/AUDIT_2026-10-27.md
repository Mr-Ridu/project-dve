Notable architecture facts that the audit confirms:

- Every public page renders from the project's own templates; the old
  `legacy/` mirror and `wastage/` scratch are gone. `core/site_pages.py` is an
  in-memory text registry (56 pages) read through `core/page.html`.
- One access predicate (`tutorials/access.py`) decides catalog, detail and
  playback. Nothing else branches on access.
- The player is a two-stage handshake: `authorize` mints an opaque token,
  `redeem` exchanges it for signed playback after a second access check.

## 3. Security posture

| Area | Verdict | Evidence |
|---|---|---|
| Access control | **OK** | Single predicate, re-evaluated per request; unpublished = hard 404 for everyone including grant holders; revocation wins on the next request (`tutorials/tests_catalog.py`, `tests_playback_provider.py`) |
| Playback tokens | **OK** | 32-byte `token_urlsafe`, cached with `{user_id, tutorial_id}`, 300 s TTL, **consumed on redeem**, second `can_access()` before signing; replay → 403 |
| Signed playback | **OK** | Bunny token `SHA256(key + video_id + expires)` built server-side; the key never reaches the browser (asserted by test). `BUNNY_EMBED_TTL` = 1 h |
| YouTube provider | **Accepted trade-off** | Privacy-enhanced `youtube-nocookie.com`; unlisted id is visible in the iframe (F10) |
| Video upload | **OK** | Extension allow-list, 2 GB cap, streamed (never buffered), upload-before-save, orphan cleanup, credentials only in request headers, staff-only + rate limited (30 / 15 min) |
| Thumbnail upload | **OK but unused** | Extension + 5 MB validators on the model field; no template renders it (F4) |
| Credential handling | **OK** | Keys come from the environment only; `.env` is gitignored; no value in logs, audit detail or error text (leak tests in `tests_throttle.py`) |
| CSRF | **OK** | Middleware on; `@csrf_protect` on the playback and progress endpoints; every POST form carries a token; all mutations POST-only |
| Open redirects | **OK** | `?next=` and the dashboard `next` field validated with `url_has_allowed_host_and_scheme` |
| Auth brute force | **OK (custom login)** | Per (IP, username) throttle, 5 failures / 5 min, success clears the counter. Django **admin login is not throttled** (F6) |
| Password policy | **OK** | All four Django validators enabled |
| Staff boundary | **OK** | `staff_required` on every dashboard view; anonymous → login redirect, non-staff → hard 403; no self-approval; every mutation audited with the direct-socket IP |
| XSS | **OK** | Autoescape everywhere; no `\|safe`/`mark_safe` in the codebase; `escapejs` used in the player bootstrap; search output escaped |
| SQL injection | **OK** | ORM only, no `.raw()`/`extra()` |
| Clickjacking | **OK** | `X_FRAME_OPTIONS = DENY` (prod) |
| Transport / cookies | **OK** | `DEBUG=False`, `SECURE_SSL_REDIRECT` (default on), `SESSION_COOKIE_SECURE/HTTPONLY`, `CSRF_COOKIE_SECURE`, `SameSite=Lax`, nosniff, `Referrer-Policy: same-origin` |
| HSTS | **Configurable, off** | `SECURE_HSTS_SECONDS` defaults to `0` by design until the certificate is verified (deploy-check W004 — expected) |
| Content Security Policy | **Missing** | No CSP / `Permissions-Policy` header anywhere (F7) |
| Secrets in repo | **OK** | Nothing tracked; `db.sqlite3`, `.env`, `media/`, `staticfiles/` are gitignored |
| Error handling | **BROKEN (F1)** | `handler500` points at the 404 view → an unhandled exception answers **HTTP 404 "Page not found"** |

## 4. Privacy review

**Data held per account:** username, first/last name, email, approval status
(+ who approved and when), `access_all_tutorials`, per-tutorial watch progress
(seconds, percent, completed). No phone, address, payment or health data.

**Data in the audit log:** actor, action, target account, free-text detail
(tutorial slug / flag value, capped at 255 chars), timestamp, **client IP**.

**Cookies:** `sessionid`, `csrftoken` only. YouTube embeds use the
privacy-enhanced domain, so no Google cookies are set before a viewer presses
play. No analytics, no pixels, no third-party fonts — the fonts are self-hosted
and the old tracker/live-chat remnants were removed with the mirror.

**Third parties:** Bunny Stream (video bytes, viewer IP at play time) and
YouTube (only for YouTube-hosted tutorials, only after play).

**Exposure paths checked:** the catalog and search expose titles, descriptions
and page text only; per-account data is staff-only; playback responses carry no
account identifiers; the 403/429/503 bodies leak nothing.

**Gaps:** no retention policy for access logs, no self-service data export or
deletion, and the privacy policy page is copied from another company (F3).
GDPR basis, retention windows and the data-processing agreement with Bunny must
be documented by the owner before launch.

## 6. What is in good shape (worth keeping)

- **One authorization choke point.** Catalog, detail, progress and playback all
  call `can_access()`; the templates only *hide* links, they never decide.
- **Defence in depth on playback.** Opaque token → one-time redeem → second
  access check → server-side signing. Replay, expiry and revocation are all
  tested.
- **Staff operations are auditable.** Approvals, grants, revocations, tutorial
  edits and deletions write an `AuditEvent` with actor and direct-socket IP.
- **Uploads never touch local disk** and never expose credentials; failures
  leave the previous video attached.
- **No third-party runtime dependencies** beyond Bunny/YouTube at play time:
  fonts are self-hosted, no analytics, no trackers.
- **Accessibility baseline:** skip link, semantic landmarks, labelled icons,
  `alt` on every image, focus styles, reduced-motion rules, an explicit
  accessibility stylesheet loaded after the Tailwind bundle.
- **199 tests** cover the shell, URL map, static resolution, access matrix,
  tokens, signing, throttling, uploads and the staff gate.

## 8. Verdict

The security architecture is sound: authorization is centralised and
re-checked, tokens are short-lived and single-use, CSRF and upload handling are
correct, credentials stay server-side, and the staff boundary is enforced and
audited. The full suite (199 tests) passes, model migrations are in sync, and
the deployment check reports only the two deliberate warnings.

What is **not** ready is the surrounding operational and legal layer: a
server-error handler that reports 500s as 404, no password recovery, an
uncommitted working tree, and a site whose text, imagery and legal pages are
still another company's. Those are the items to close before this is handed to
the client.
