## 2. Rate limiting — added this pass

`core/throttle.py`: cache-based counters per **(action, client IP, account)**.
Same convention as the existing `accounts/throttle.py` (no external
dependency; LocMem in dev, shared database cache in production, so counters
are shared across workers there). Limits live in `settings.RATE_LIMITS` and are
read at request time, so a deployment or a test can retune without touching
call sites. Exceeding a limit returns an honest **429** (JSON for the playback
APIs, a styled page elsewhere) — never a silent drop.

| Scope | Limit | Endpoint(s) |
|---|---|---|
| `auth` | 5 failures / 5 min (existing) | login, register |
| `playback` | 60 req / 5 min | `POST /tutorials/<slug>/authorize/`, `POST /tutorials/redeem/` |
| `progress` | 120 req / 5 min | `POST /tutorials/<slug>/progress/` |
| `forms` | 30 req / 5 min | `POST /forms/placeholder/` |
| `search` | 60 req / 5 min | `GET /search/` |
| `upload` | 30 req / 15 min | dashboard tutorial create/edit (uploads included) |

Design notes:

- Identity is the account id when signed in, `"anon"` otherwise — one noisy
  account cannot lock out everyone behind the same NAT.
- The brake sits **in front of** authorization; it never grants anything.
  `tutorials/access.py` still decides every request.
- Normal use is far below the limits (a play = 2 requests; playback allows
  ~30 plays per 5 minutes per account).

## 4. Privacy review

- **Data held per account:** username, name, email, approval status + who/when,
  watch progress per tutorial. No phone, address, payment or health data.
- **Cookies:** `sessionid` and `csrftoken` only. The YouTube embed uses
  `youtube-nocookie.com`, so no YouTube cookies are set before a viewer presses
  play. The legacy mirror is sanitized — third-party trackers were already
  stripped.
- **Third parties:** Bunny Stream (video bytes, viewer IP at play time),
  YouTube (only for YouTube-hosted tutorials, and only after the viewer plays).
- **Logging:** registration logs the username at INFO (not the email); the
  audit log stores actor, action and direct-socket IP. IP retention policy is
  a business decision — recommend a 12-month cap.
- **Exposure paths checked:** no email/PII in public catalog or search output;
  per-user pages are staff-only; playback responses carry no account data.

## 7. Verdict

The authorization, token, CSRF, upload and credential-handling paths are sound
and now covered by tests including the new rate limits. Two operational items
must be closed before handover: **F1** (the API key does not work) and **F2**
(rotate the exposed keys). F4 is a hardening nicety; F3 is an accepted,
documented trade-off of the budget decision.
